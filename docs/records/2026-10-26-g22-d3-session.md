## 1. Terms

| Term | Meaning |
|---|---|
| BG | Background preservation. The PocketRisu server runs a whole chat generation (prompt assembly, model call, post-processing, chat commit) without the browser. |
| RCM 1.0.21 | A third-party memory plugin. The project uses its original JS and backend unmodified. After an answer, RCM schedules a 1500 ms one-shot timer inside its `afterRequest` hook. When the timer fires, it calls its backend again (`/v1/turn/prepare`) to sync the output. |
| afterRequest | A plugin hook (a "replacer") that runs on the model output before the chat is committed. |
| G2.2 | The plan stage "API and call semantics" for running official RCM inside BG. Its units are G2.2a/b/c, D1-a, NF-1, D2, D3 and D4. |
| D3 | The G2.2 unit "BG output sync after the RCM response". It continues the afterRequest one-shot timers once, after the commit, inside a bounded window. |
| D3-1 | The single commit-unit ID in the D3 plan's unit table: `D3-1 \| Post-commit continuation for afterRequest timers`. |
| Window | The post-response window. After the commit, the host keeps the plugin session open until the kept timers and their work end, or until a deadline. |
| S4b | The orchestrator's detached full-generation stage. It runs generation and then commits the answer to the normal chat. |
| N+1 | The next user message in the same chat. |
| ACK | The client's acknowledgement of a terminal result. The server then deletes the stored result and marks the operation `delivered`. |
| Lease | The object that S4b receives in order to keep the plugin host and chat lock open past the commit. |
| Candidate gate | `pocketrisu-candidate-gates.sh`, a 19-step check. It covers the dist build twice, repository tests, and apply onto a pristine PocketRisu 1.10.0. On that composed tree it runs `pnpm test` (client and server vitest), `test:compat`, `pnpm check`, `pnpm build` and the BG bundle, followed by an apply→revert round trip. |
| Probe | A `scripts/probe-*.cjs` file that runs against a composed tree with real worker processes, through `run-probe.sh`. |
| `[new]` / `[unchanged]` | Contract tags in test titles. A `[new]` test must fail before the implementation on a behavior assertion. An `[unchanged]` test must pass before it. |
| Astra, Argon, Codex | External reviewers and authors from other model families. Astra is `gpt-6-astra` (plan review). Argon is Gemini 4 Argon (test scenarios). Codex is `gpt-5.6-sol` (blind tests) and `gpt-6.1-sol` (code review). |
